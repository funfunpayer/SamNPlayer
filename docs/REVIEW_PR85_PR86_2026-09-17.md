## Was die neuen PRs gut machen

**Der Script Doctor läuft jetzt ohne Python – und liefert dieselben Zahlen.** `funscript/script_quality.go` ersetzt in `generator.ScriptQuality` den Python-Unterprozess (`FindPython` + `CheckDependencies` + `writeScriptToTemp` fallen weg). Ich habe die Portierung nachgemessen, statt sie zu glauben: ein synthetisches Skript mit 283 Aktionen, einer 2-Sekunden-Lücke und einem Geschwindigkeitssprung, durch beide Implementierungen geschickt.

```
Python quality_doctor.evaluate():  score=0.770  passed=True
Go     EvaluateScriptQuality():    score=0.770  passed=true
```

Identisch, inklusive aller drei Warntexte im Wortlaut. Das ist genau der Punkt 6.1 aus der ersten Bewertung, und er ist sauber umgesetzt – die Prüfung eines importierten Funscripts braucht keine Python-Installation mehr.

**Die Go-Portierung der Nachverarbeitung ist mit Golden-Daten abgesichert.** `generator/posttrack` (Savitzky-Golay, Peak-Erkennung, Normalisierung, Keyframes) prüft gegen `testdata/positions_goldens.json` mit 10.989 Zeilen aus der Python-Referenz, 82,1 % Abdeckung, und baut ohne OpenCV. Das ist die richtige Methode für eine Portierung: nicht „sieht gleich aus", sondern punktweiser Abgleich gegen die alte Implementierung.

**Der native Tracker ist echtes Opt-in mit Stub.** `NativeTrackingAvailable()` in zwei Varianten (`native_track_opencv.go` / `native_track_stub.go`) statt eines harten Zwangs – Punkt 7 der ersten Bewertung, im Prinzip erledigt. Die Bedingung ist allerdings falsch gewählt, siehe unten.

**Der Suction-Doppelboden ist ein echter Fund.** Die Änderung in `funscript/mapper.go` verhindert, dass `liftFloor` einen Boden auf Werte legt, die im Skript schon geklemmt sind (0,20 → 0,36 bei `MinSuction=0.20`). Der Kommentar nennt Ursache, Rechenweg und Beleg. Genau so sollte ein Fix aussehen.

**Formatierung und Prüfer sind grün.** `gofmt -l` leer, `go vet` ohne Befund auf beiden Zweigen. Abdeckung von `funscript` steigt von 79,1 % auf 82,9 %.

## Neue Befunde

### 1. Bug: unsortierte Zeitstempel werden nie gemeldet (`funscript/script_quality.go`)

Der Kommentar sagt: „Work on a time-sorted copy; **unsorted input is still flagged**." Das tut der Code nicht. Erst wird sortiert, dann wird auf der sortierten Kopie geprüft:

```go
sorted := append([]Action(nil), actions...)
sort.SliceStable(sorted, func(i, j int) bool { return sorted[i].At < sorted[j].At })
at := make([]float64, len(sorted))   // ← at kommt aus sorted
...
for i := 1; i < len(at); i++ {
    if at[i] < at[i-1] {             // ← kann nie zutreffen
        warnings = append(warnings, "Zeitstempel nicht aufsteigend sortiert")
```

Die Bedingung ist nach dem Sortieren unerfüllbar, die Warnung ist toter Code, und `penalty += 0.3` greift nie. Nachgewiesen mit einem Test gegen bewusst unsortierte Eingabe:

```
score=1.000 passed=true warnings=[]
```

Ein Skript mit rückläufigen Zeitstempeln – der klassische Fehler beim Zusammenschneiden zweier Skripte – erhält also die Bestnote. Die Python-Vorlage prüft an derselben Stelle vor dem Sortieren, deshalb fällt der Unterschied im Score-Vergleich nicht auf, solange man nur sortierte Eingaben testet. Genau das tun die 112 Zeilen `script_quality_test.go`.

**Fix:** die Reihenfolge auf `actions` prüfen, bevor die Kopie sortiert wird, und einen Testfall mit unsortierter Eingabe ergänzen. Beides zusammen unter 15 Zeilen.

### 2. `go build ./generator` schlägt ohne OpenCV fehl (PR #85)

Die Build-Bedingung ist `//go:build cgo && !windows`. `cgo` ist auf jedem Linux-/macOS-Rechner mit C-Compiler standardmäßig **an** – die Bedingung fragt also nicht „ist OpenCV da", sondern „gibt es einen C-Compiler". Ergebnis auf einer normalen Entwicklungsmaschine ohne OpenCV-Header:

```
$ go build ./generator/
# github.com/funfunpayer/SamNPlayer/generator/trackcv
Package opencv4 was not found in the pkg-config search path.

$ CGO_ENABLED=0 go build ./generator/
(OK)
```

Auf `main` betraf das nur `generator/trackcv`, ein Paket, das niemand importiert. Mit PR #85 hängt das **Hauptpaket** `generator` daran, und damit `cmd/gui-wails` und `cmd/cli`. Ein frischer Klon lässt sich ohne `libopencv-dev` nicht mehr bauen und nicht testen. Die CI verdeckt das, weil sie `libopencv-dev` installiert – der Contributor sieht es sofort.

**Fix:** ein eigener Opt-in-Tag statt `cgo` als Stellvertreter:

```go
// native_track_opencv.go
//go:build cgo && opencv && !windows

// native_track_stub.go
//go:build !cgo || !opencv || windows
```

Gebaut wird der native Pfad dann bewusst mit `-tags opencv` (Release-Workflow und der OpenCV-Job der CI), alles andere fällt auf den Stub zurück. Denselben Tag braucht `generator/trackcv` selbst, sonst bleibt `go test ./...` weiter an ihm hängen.

### 3. Keine Paritätsprüfung zwischen Go und Python für den Script Doctor

Dass beide heute dasselbe ergeben, habe ich gemessen – aber nichts hält das fest. `generate_funscript.py --script-quality` existiert weiter, samt `generator/script_quality_test.py`, und `quality_doctor.py` bleibt der Weg für die Prüfung während der Generierung (mit dichtem Signal). Es gibt also weiterhin zwei Implementierungen derselben Schwellwerte, jetzt nur ohne den Zwang, sie gleich zu halten. Beim ersten Nachjustieren einer Konstante auf einer Seite driften die Urteile auseinander, und der Nutzer sieht für dieselbe Datei zwei verschiedene Scores.

**Fix:** dasselbe Muster wie in `posttrack` – eine Handvoll Funscripts plus die von Python erzeugten Ergebnisse als Golden-JSON einchecken, ein Go-Test vergleicht `EvaluateScriptQuality` dagegen. Das kostet einmalig eine Stunde und macht Drift zu einem roten Test statt zu einem Nutzerbericht.

Mittelfristig sauberer: die dichte-signal-Prüfungen ebenfalls nach Go ziehen und `--script-quality` samt `quality_doctor.py` löschen, damit die Frage „welche Zahl gilt" nicht mehr existiert.

### 4. `funscript/phase.go` ist der vierte unbenutzte Baustein

Der Phase Analyzer (305 Zeilen plus 152 Zeilen Test, `BestLagCorrelation` und `DiagnosePhase`) wird von keinem Aufrufer im Projekt verwendet – kein GUI-Binding, kein CLI-Kommando. Er tritt damit neben `sam`, `videox` und `trackcv`. `funscript/device_compat.go` ist besser dran, das wird von `script_quality.go:136` genutzt.

Inhaltlich ist er gut gebaut (Nil-Zeiger für „undefiniert" statt 0,0, Konstanten explizit an `fungen_compare.py` gespiegelt). Aber solange kein Nutzer ihn erreicht, ist er reine Wartungslast, und die Portierung von `fungen_compare.py` hat dieselbe Drift-Frage wie Punkt 3. Ein verstecktes CLI-Unterkommando (`SamNPlayer-cli phase a.funscript b.funscript`) würde reichen, um ihn nützlich und geprüft zu halten.

### 5. Statusdokumente wachsen weiter

PR #86 fügt 540 Zeilen Dokumentation hinzu, darunter ein neuer Ordner `docs/perception_update_2026-09/` mit 12 Dateien plus `architecture_decisions.json` und `09_findings.csv`, dazu `docs/FINDINGS_TIMING_TF.md`. Der Inhalt ist gut – Befunde mit Messwerten. Die Form ist das Problem: datierte Zustandsordner sind in vier Wochen historisch, stehen aber gleichrangig neben `docs/SAM_ARCHITECTURE.md`. Der Befund zum Suction-Doppelboden gehört als Kommentar an den Code (dort steht er auch) und als Zeile in `CHANGELOG.md` – nicht zusätzlich in drei Dokumente.
